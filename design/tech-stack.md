# 线上造景贴纸游戏 · 技术选型

2026-11-20 · 首期目标为手机浏览器邀请试玩，桌面浏览器支持鼠标。第一盒沿用《周末小镇》的手绘风格和 14 张独立透明贴纸。

## 采用的技术

| 环节 | 选择 | 选择理由 |
| --- | --- | --- |
| 游戏客户端 | Godot 4.7.2 Standard、GDScript、2D、Compatibility、单线程 Web 导出 | 沿用已选引擎。一套场景处理触屏和鼠标，HTML 链接即可试玩。固定编辑器和导出模板版本，便于复现构建。 |
| 场景与触控 | Node2D 绘制场景和目标轮廓，Control 绘制贴纸托盘与按钮 | 斜俯视效果来自原画。采用固定逻辑坐标、绘制层级与不透明像素命中，足以表达拼图关系。 |
| 素材与关卡 | PNG 母版、带 alpha 的运行时 WebP、版本化 JSON | 一件一图。相同素材可以在多套布局中复用。完成图和重拼目标始终来自同一份布局。 |
| 本地进度 | Web 使用 localStorage 同步保存小型 JSON；桌面引擎使用 FileAccess 和 user:// | 首关免注册。每次确认落贴便保存，刷新后按盒子版本还原。 |
| 网页发布 | 同源 HTTPS 静态资源；独立定制包按需下载 | 浏览器先加载游戏和公共首盒。分享接收方只需读取已经生成的素材。用静态托管的日志测首开，不预购多地域基础设施。 |
| 邀请制服务 | Python 3.12、FastAPI、SQLite，单机持久化磁盘与备份 | 到定制和分享阶段再部署一个服务，记录盒子、作业、交付和漏斗事件。一个独立工作进程从同一个 SQLite 作业表取任务；这个规模适合少量并行订单。 |
| AI 图像 | 服务端逐件生成，提供商先用同一组样题做画质与成本对照 | 国内候选为阿里云万相加透明底处理，海外候选为 Recraft。运行时通过文件和清单读取结果，游戏不直接调用供应商。 |

Godot 4.7.2 提供标准编辑器和配套 Web 模板。Godot 4 的网页导出依赖 WebAssembly 和 WebGL 2；单线程模式便于普通静态托管。iOS Safari、Android Chrome 和应用内浏览器分别实测。美术与关卡数据可供后续原生端使用，微信小游戏需要单独验证运行环境。[Godot 4.7.2 官方归档](https://godotengine.org/download/archive/4.7.2-stable/) · [Godot 网页导出说明](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html)

### 已验证的 Web 构建链

在临时目录使用官方编辑器 `4.7.2.stable.official.ed1daf0bf` 和同版本的单线程 Web 发布模板，建了一个含现有小狗精灵的最小 2D 场景。无头导出成功，通过本机 HTTP 服务打开产物。Windows 无头 Chrome 132 使用 SwiftShader 创建 WebGL 2 上下文，GDScript 回报已执行第 12 帧，画布像素检查确认精灵实际绘出。

这次导出的 wasm 为 39,514,754 字节，离线 gzip 后为 10,114,291 字节。wasm、pck、JavaScript 三项 gzip 后合计约 11.52 MB（十进制），其中只有一张未按运行尺寸缩小的贴纸。以 10 Mbps 估算，仅传输这三项便需约 9.2 秒。首期用轻量 HTML 先展示开盒画面、加载状态和重试按钮；埋点从访问网址开始计时，把引擎下载与开盒后等待分别记账。正式站压缩响应、手机冷启动、整盒拖放和存档在首个试玩版本继续实测。

## 一盒贴纸对应什么数据

1. **素材清单**描述“能拿起什么”。源清单已有文件名、建议显示高度、原图尺寸和可见范围。运行时为每件分配稳定的素材 ID。生成图裁掉透明边距时同步换算锚点、绘制矩形和点选区域。
2. **关卡布局**描述“这一关怎样才算拼完”。每个可放置实例有唯一槽位 ID，引用素材 ID，记录目标位置、绘制顺序和可接受距离。底板装饰与待拼槽位分别声明。预览由底板及这些实例绘出。发布后盒子版本保持可读取，改位置或改图另存新版本。
3. **玩家进度**描述“这个人拼到了哪里”。保存关卡 ID、版本和已放好的槽位 ID。同一素材有两个实例时分别计数；后台挂起或刷新后不重复计算已贴数量。进度带结构版本；读取失败时仍能进入关卡并提示用户选择重新开始。
4. **分享记录**引用盒子版本和目标布局。公共样板可用固定链接；定制盒使用随机、高熵、不含玩家输入的分享标识。朋友打开同一套素材，从自己的空白进度开始。只有玩家主动分享后才生成对外链接，可撤销访问。

## 手机网页的实现要点

- 把画布内的输入换算到关卡逻辑坐标，窗口改变时重算视图。单指从托盘揭取、拖动、松手吸附，另提供“点选贴纸、点目标位”的操作。小狗、椅腿等细部扩大屏幕触控区域；相邻区域冲突时优先真正命中的不透明像素，再比较最近目标。首关保持贴纸原画方向与比例。
- 使用有版本的静态路径，保留导出文件同目录关系。为 wasm 返回 application/wasm，pck 返回 application/octet-stream，开启 Brotli 或 gzip；更新时先传资源、后切换入口，保留旧版本供回放。
- 浏览器版本将已放置的目标 ID 顺序写入 localStorage。后一动作在贴纸落位时同步完成，用户刷新后即可续玩。首次开盒手势启动声音；存储不可用时允许本次继续拼，并在适当位置说明本次进度保存状态。验收要覆盖刷新、切后台、手机安全区和浏览器工具栏伸缩。[Godot 网页浏览器限制](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#limitations)

### 实测素材预算

对现有 14 张 PNG 做了内存内编码对照。按 alpha 裁掉全透明边缘，保持长宽比，把可见高度缩到清单建议显示高度的两倍，上限为母版尺寸。

| 全部 14 张贴纸 | 实测体积或估算内存 |
| --- | ---: |
| PNG 母版文件 | 23.16 MiB |
| 原尺寸 RGBA8 像素 | 84.00 MiB |
| 缩放后的无损 WebP 文件 | 2.09 MiB |
| 相同尺寸的 WebP，质量 88 | 0.63 MiB |
| 缩放后的 RGBA8 像素 | 10.84 MiB |

首轮默认采用缩放后的无损 WebP。首屏预算吃紧时，再在手机上比较有损版本的水彩纹理、细线和半透明边缘。表中的文件大小仅涵盖贴纸；浏览器实际传输、WebAssembly 下载、Godot 导入后的资源体积、运行内存和首个可操作时刻都要在导出版本中另测。原画与原资源包继续作为美术母版。

## AI 定制与交付

玩家描述 → 确认组件清单 → 服务端为每个组件生成图片 → 检查并补做失败项 → 配置并预览目标布局 → 发布不可变盒子版本 → 通知玩家可拼。

- 首轮在后台由运营确认清单、脚点、层级与布局。一个摊位、一个店员、一个路灯分别生成。一张图可以包含角色手中不可拆的乐器。审核包括透明通道、裁边、物件完整性、朝向、相对比例以及拼完后的遮挡。
- 每项任务使用订单、组件和尝试次数组成的标识。请求重发或页面刷新复用已有作业；保存供应商任务编号后可查回结果。Worker 采用带到期时间的领取状态以便中断后恢复，按件重试并计费。全部通过后一次性发布清单；失败项可替换或人工退还额度。
- 分享和重玩只读已归档文件。服务端保管 API 密钥，校验输入长度、允许的文件类型和单盒预算，限制匿名请求频率。邀请制先接受文字；公开展示由作者选择并经审核。若进入公开运营，按发行地区核对 AI 生成标识和内容规则。[中国网信网《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)
- 试产记录每件尝试、每盒人工分钟数、可交付耗时、退回原因与真实成本。按实际交付效果选择模型。供应商价格只用于预算，成套画质以盲评和手机实机为准。[阿里云万相](https://help.aliyun.com/zh/model-studio/wan2-7-image) · [腾讯云透明底处理定价](https://cloud.tencent.com/document/product/460/58118) · [Recraft API 价格](https://www.recraft.ai/pricing?tab=api)
